## Sound protocol boundaries

Same-digest raw bytes supply both metadata and exact scorer text; no unverified reread or source/manifest mutation is allowed. Exact whole-name/code matching, CIK digit normalization, explicit source declarations and conflict refusal are materially safer than document-ID inference, suffix deletion, synonym tables or external company lookup. They will also refuse some real supplied sources: for example, punctuation in a flattened legal name can differ from the task's spelling, and table components may use abbreviations absent from the declared task name. Those refusals must be recorded rather than patched with a coverage-driven alias list.

Whole paragraphs, all original pipe rows/columns, explicit publication/vintage availability and retained accounting units prevent a source binder from silently becoming a numerical feature compiler. The fixed 32768-byte/four-range context budget is a feasibility limit, not a guarantee that flattened SEC evidence fits. Preserving guidance as forward context and generic could-default language as conditional context does not license a future EPS or distress assertion. Unknown families and ambiguous owners remain explicit holes. All eligible candidate contexts should be inspected in the fixed ID/offset order with independent inspection of every admitted bundle.

## Required mechanical pins before a later binder

1. Define a structural financial-table predicate beyond merely finding `|` and uniform row cell counts. Require a complete header and at least one actual data row, retain separators without treating them as data, and specify the date/series/financial-header grammar for the relevant family. A singleton prose line or navigation line cannot be accepted as a table. The fixed inventory includes a flattened Apple 10-K first pipe-containing line spanning characters 0..200001 (202697 UTF8 bytes) and `Release Calendar | Blog` navigation fragments. They must be rejected as malformed/oversized contexts, never treated as a compact financial table or admitted by coincidental keyword presence.
2. Define whether the source-introduction cutoff uses the first structurally valid table or any pipe run, and how a prefix ending mid-line/sentence is removed. The present phrases permit different implementations. If a malformed inline pipe erases an otherwise explicit registrant introduction, report a refusal; do not silently invent a different introduction rule after coverage. Flattened single-line filings also need an exact complete-boundary rule so the fixed prefix is not treated as an admitted paragraph.
3. Pin exact registrant/press-release/local-attribution cue grammar and the finite span in which conflicting issuer declarations are searched. A company name anywhere in a filing plus a generic heading is insufficient to make a counterparty or affiliate statement the registrant's financial fact. CIK/ticker conflict must veto rather than be outvoted. Require explicit local table/section attribution or refuse; first-person wording alone cannot resolve a multi-issuer discussion.
4. Pin executable period, unit, basis, availability and conditional-context predicates per family before fixtures. Specify which missing conditions always refuse, which optional distinctions are required only when stated, the exact calendar formats and treatment of ambiguous report-date versus publication-date headers. Whole-table future-vintage refusal needs a typed availability rule so a promised future release date is not mistaken for a realized observation. Never infer reporting columns or financial scales from magnitudes.
5. Specify contiguous paragraph/table/intro attachment, range overlap/deduplication, compact JSON serialization and all receipt metadata in the 32768-byte cap. No clipping, transformed values or dropped qualifier is allowed. Adjacent paragraphs needed for credit negation/mitigation consume the same fixed budget. A complete oversized flattened paragraph is a source hole.
6. Specify whole-code boundaries and Unicode behavior, including an ASCII code attached to other letters/digits/underscore or mixed-script text. Distinguish repeated same-series entities for different reference months from a code mapped to conflicting series names; each entity still needs its exact original row-period label. The normalization must preserve punctuation and parenthetical contract qualifiers as promised.

Freeze these definitions, their synthetic adversarial fixtures, expected refusal codes and baseline/input hashes before any binder execution. Test wrong CIK with matching name, matching CIK with wrong body declaration, competitor quotations, repeated/ambiguous legal names, inline pipes, missing/swapped headers, future vintage, guidance dates, Unicode offsets and oversized whole blocks. Inspect all later admitted contexts independently; code passing controls does not establish actual source coverage.

## Disposition

Accept the current 11/78/69 inventory and its zero-to-78 bounds as mechanically verified source-only planning. Preserve v7, rejected v8 and submitted runtimes. Do not yet authorize a binder from the semantic prose alone; its deterministic source predicates require the pins above and root authorization. Even a successful source audit would only justify a separately reviewed projection hypothesis and genuine matched financial evaluation, with unsupported exact-v2 fallback and full-roster accounting. No submission or performance/accuracy claim follows from v9.
