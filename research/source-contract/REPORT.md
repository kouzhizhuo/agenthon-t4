# Current source contract diagnosis

The V8 empty-ownership fallback rejection is a valid protocol feasibility failure. It also exposes a mismatch between our old adapter's optional ownership fields and the organizer's actual checksum-manifest contract. All 69 public documents are declared and hash-verifiable, but the manifests do not declare `entity_ids` or `shared`.

The organizer's [authoring guide](/Volumes/Alan/Nips_com/Agenthon-2026/04_track4_explainability/docs/AUTHORING-GUIDE.md:88) describes the root manifest as a per-file checksum ledger. Document metadata lives in the JSON documents and task. At line 119, the guide says document-ID internals have no semantic contract; at line 123, CIK/ticker/title fields are useful retrieval provenance, and says “do not build a contract on them.” `CorpusIndex` resolves manifest membership, digest and date; it does not promise issuer or series ownership.

Exact V2 `evidence_for` computes the empty optional-owner `permitted` pool, then uses `permitted or docs`. Its unchanged `Retriever` ranks 1000-character overlapping windows by identity binding and token relevance. `binding` favors CIK inside the manifest document ID, exact series/entity tokens in title or the first 7000 characters, normalized issuer names, or tenor text. These mechanisms can make useful evidence visible but are heuristics; source-ID naming is explicitly a convention, not an ownership schema. V2 does not convert the raw document CIK/ticker/series fields into ownership labels.

Exact V2 `quote_claims` separately requires the optional manifest `entity_ids` or `shared` fields. Consequently no public corpus span is admitted as an output claim through that branch; it falls back to exact task-row feature quotes. `reason_passages` still uses retrieved original source windows, so optional submitted reasons can carry corpus coordinates. Source retrieval, claim selection and reason evidence therefore have different admission rules. This is a source-mechanics diagnosis, not a causal attribution of official V2/V4 scores or proof of financial prediction quality.

The saved `EXACT_METADATA_MATCHES.json` compares only supplied task/document fields after checking each raw document against its manifest digest. It finds exact CIK/ticker equality for all 26 issuer entities and exact task/document `series_id` equality for 12 macro-revision entities: 38/78 total. The other 40 entities include auctions, COT, CPI components and FOMC rates. No document-ID parsing, normalized-name map or guessed shared-owner map was constructed. Metadata equality identifies an auditable retrieval clue; the task period, source/units and local owner must still be retained and independently checked in any future separate evidence protocol.

No model call, forecast, source-value conversion, replacement admission policy, projection or organizer-file mutation occurred. A future method must declare its use of optional same-digest metadata and source anchors explicitly, with safe unsupported/ambiguous fallback, before code and outcomes. The rejected V8 protocol remains unchanged.
